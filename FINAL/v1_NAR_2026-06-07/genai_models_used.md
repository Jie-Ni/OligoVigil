**Cross-check with audit CSV header.** `04_delivery/v2_human_override_decisions.csv` columns:
`candidate_id, entity_table, entity_id, pmid, doi, source_location, v1_keyword_decision, v2_llm_proposal, human_decision, human_grade, is_observed_experimental, is_computational_prediction, current_validation_status, curator_id`.
Note: the override CSV stores the v2 *proposal* (`v2_llm_proposal`) but does **not** expose a per-row `extractor_model` column — model attribution lives in the upstream proposal CSVs written by the scripts above (where `extractor_model = "<script>:<model>"` is one of the four strings tabulated). Sampled rows all carry `curator_id="ni_jie"` and `current_validation_status="curator_verified"`.

**What is not used in this project.** No OpenAI / GPT API call, no Cohere, no local open-weights LLM, no embedding model, no fine-tuning, no RAG retriever beyond the deterministic local PMC-XML / cached-PubMed-abstract loader. The only two external model APIs touched by the curation scripts are Anthropic (`claude-opus-4-8`) and Google (`gemini-2.5-flash`).

**Open verification item for the PI.**

This is an internal short form, not a canonical Anthropic public model ID (which currently take the form `claude-opus-4-5-YYYYMMDD`, `claude-sonnet-4-5-YYYYMMDD`, etc.).
